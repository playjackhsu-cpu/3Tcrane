# OCR 與逐題審查流程

## 目的與邊界

OCR 只建立可搜尋的「候選文字」，不是正式題庫。原始 PDF、切頁影像、OCR 原文、內部頁碼、信心值與審查意見均留在 `PrivateResources/`；公開 Git 與 App 只接收已逐題核准的結構化內容。自 2026-08-11 起，後續審查以主管機關提供的可擷取文字 PDF 與官方線上資料為主，既有 OCR 僅作缺頁、文字不清或來源衝突時的備援，不再重複執行整批 OCR。

本次收件的來源為 38 頁 A3 橫式掃描 PDF，多數 PDF 頁同時拍攝左右兩個書頁，沒有可擷取文字層。封面標示「吊升荷重在三公噸以上固定式起重機操作人員技能檢定學術科測試參考資料」、中華民國工業安全衛生協會、115 年 6 月印製。持有紙本或 PDF 不代表已有公開重製、改作與散布權，權利確認前不得公開整批題文。

## 五層資料分離

| 層級 | 內容 | 可進公開 Git | 可進 App |
| --- | --- | --- | --- |
| 原始證據 | PDF、原始頁、授權證明 | 否 | 否 |
| OCR 證據 | 增強影像、raw text、TSV 座標／信心值 | 否 | 否 |
| 審查台帳 | 原稿定位、答案衝突、審查者、修訂歷程 | 否 | 否 |
| 公開候選 | 穩定 ID、題文、選項、解析、公開來源、權利狀態 | 只有已清權內容 | 否 |
| 發行題庫 | 通過 schema、內容與 App 測試的版本 JSON | 是 | 是 |

## OCR 處理

1. 收件時記錄檔案雜湊、大小、頁數、是否加密、是否有文字層及封面版本。
2. 以 300 DPI 逐頁渲染，不修改原始 PDF。
3. 將雙頁影像切成左、右書頁，保留少量書脊重疊，做灰階、自動對比與銳化。
4. 以繁體中文加英文辨識，保存原始文字與 TSV；不得先人工「修好」OCR 原文。
5. 逐批抽查裁切是否漏字。不同頁面若有位移、陰影或透視，個別調整，不能沿用錯誤裁切。
6. OCR 結果固定標記 `ocr-raw-needs-line-review`，不得直接轉為 `Content/Releases/`。

本機工具為 `Scripts/content/ocr_question_bank.py`。它強制把輸出限制在 `PrivateResources/`，並產生處理 manifest；使用方式見 `Scripts/content/README.md`。

### 2026-08-10 首次執行結果

- 38 個 PDF spread 全部完成，產生 76 個左右書頁候選。
- 74 個含文字候選的 Tesseract 平均字詞信心約 80.68%；2 個空白／非文字頁沒有分數。
- 最低分頁面主要是內容稀疏，不代表可免除人工核對；每頁仍須看圖。
- 首批 9 題已完成逐字比對與官方法規查核：8 題答案確認、1 題有題幹適用範圍歧義；權利未確認，因此 0 題可發行。

### 2026-08-11 來源優先順序決策

1. 題文、選項、印刷答案與刪題狀態，以技能檢定中心最新可擷取文字 PDF 建立基準。
2. 現行正解優先以勞動部法令查詢系統、職業安全衛生署及其他主管機關公開資料驗證。
3. 技術題若官方參考答案合理但缺乏獨立公開依據，保留印刷答案並標記 `source-checked-needs-independent-technical-source`，不得宣稱已完成正解驗證。
4. 只有官方 PDF 缺字、題圖不清、版本互相衝突或答案定位失敗時，才回看既有掃描／OCR 證據；不再為已清楚的官方文字重跑 OCR。

官方下載頁另明示「學科參考資料僅供參考，不得做為測試試題或答案之依據」。因此官方 PDF 只能作為完整性與印刷答案證據；App 的現行正解仍須經法規或技術來源另行驗證。

## 每題逐行核對

每題以官方可擷取文字版本開始核對；OCR 不得作為唯一依據：

1. 建立穩定 `questionId`，記錄官方檔名、雜湊、PDF 頁、印刷頁碼與原題號；掃描交叉位置只留在私有證據層。
2. 依官方文字層核對題幹、數字、單位、否定詞、標點、四個選項、印刷答案與刪題狀態。
3. 對含圖題、缺字、文字抽取異常或版本衝突題才查看來源頁影像；無法判定時標為衝突，不猜測。
4. 檢查重複題、選項錯置、跨頁斷句與文字抽取常見混淆，例如 `0/O`、`1/l`、公噸／公斤、條號與電壓單位。
5. 保留既有 OCR 原文；官方 transcription 與審查修訂另存，確保可追溯，但不為已清楚題文新增 OCR 工作。
6. 題文基準確認後，才進入現行來源、答案、解析與權利驗證。

## 答案、來源與解析

- 印刷答案只是歷史證據，不能自動當成現行正解。
- 法規題優先查中華民國政府機關的現行法規、主管機關公告及官方題庫；記錄文件名稱、條／款、HTTPS URL 與查核日期。
- 技術、安全與計算題優先採主管機關、國家標準授權資料或可公開的原廠技術資料。無法公開連結的內部資料只能留在私有台帳。
- 網頁摘要、搜尋結果片段、論壇、補習班與 AI 產生內容不能單獨作為正解依據。
- 原稿答案與現行官方來源衝突時，填寫 `answerConflict`、停止該題發布並保留兩邊證據；不得用推測覆寫。
- 解析應說明判斷規則與正解理由；選擇題另寫四個選項的成立／不成立原因。另有等價解答時才填 `alternativeAnswer`。
- 每次 App 發版前重新抽查具時效性的法規來源；來源失效或法條修訂時，該題回到 `needs-review`。

## 狀態機

`ocr-raw` → `transcribed` → `source-checked` → `explanation-reviewed` → `rights-cleared` → `approved`

任一階段發現看不清、答案衝突、來源過期或權利不明，狀態退回 `needs-review`，且 `releaseEligible=false`。只有 `approved` 題目能輸出公開 release。

`deleted-retained-for-completeness` 是歷史保留狀態，不會再回到發行流程；若主管機關日後恢復該題，必須建立新的來源版本與審查紀錄，不得直接把舊題切回 active。

## 完整納入與例外清單規則

完整清冊與候選抽題池必須分開計數，禁止用「未納入」代表刪除原始紀錄：

1. 所有官方來源題目一律先進完整清冊，保留原題、印刷答案、官方狀態、來源位置與穩定 ID。
2. 除非屬於官方刪題、明顯答案／題意衝突或法規生效過渡期，題目原則上納入候選抽題池。
3. 暫不納入候選池的題目必須逐題列出，不得只留總數；清單至少包含題目 ID、科目／工作項、題號、官方 PDF 頁、原因、證據與恢復條件。
4. 明顯錯誤或法規衝突不得靠猜測改答案；保留印刷答案與現行證據，將現行答案設為未決並封鎖發布。
5. 過渡期法規題即使目前答案仍有效，也須在 App 發版日期重新查核生效日與條文版本後才能恢復候選資格。
6. 私有詳細清單與機器可讀排除清單由 `Scripts/content/build_review_exception_reports.py` 從總清冊重建，避免人工清單與資料庫漂移。

## 建議批次

- 每批 20–30 題，避免一次大量修訂而失去可審查性。
- 每批產出題號範圍、通過／衝突／權利待確認數與來源查核日期。
- 公開 PR 不附原始掃描或私有台帳，只附已清權題目、公開來源與驗證結果。
- 全部題目完成後，再建立正式科目／章節統計、抽題規則與第一個內容版本。

## 發布 gate

逐題狀態與權利通過後，仍須通過題庫 schema、重複 ID、答案索引、公開來源、敏感資訊、App decoder、iPhone／iPad build，以及舊版學習紀錄升級保留測試。Owner 核准前不提交正式題庫。
