# 內容與資料治理

## 三層資料邊界

1. 原始層（私有）：PDF／Office／掃描、原始題號與頁碼、授權證明、OCR、人工審查證據，只在 `PrivateResources/` 或 repo 外。
2. 治理層（私有或去識別）：候選題、衝突、修訂記錄、來源查核與審批；不得含個資後才可選擇公開。
3. 發行層（公開）：`Content/Releases/`，只含 App 需要且具公開權利的結構化內容。

## 題目欄位不可混用

- 考試答案：`answer`／`options`／`answerIndex`。
- 完整解析：`explanation`，不可只重複答案。
- 另外解答：`alternativeAnswer`，只有語意等價且核准才顯示。
- 公開來源：`publicSource`、`publicSourceUrl`、`publicSourceCheckedAt`。
- 匯入來源、原稿頁碼與內部定位：只在私有治理台帳，不進發行包、不顯示給使用者。

## 內容生命週期

`收到原始檔 → 雜湊與權利登錄 → OCR／結構化 → 人工校對 → 答案／解析／來源查核 → 重複與 ID 檢查 → 候選 release → App QA → Owner 核准 → 隨新版 App 發行`

任何答案衝突、來源過期、無法確認的安全／法規內容都進 `needs-review`，不得因時程直接標為 checked。

## 版本與穩定 ID

- App 版本與內容版本分開顯示，但內容只會隨 App 發行。
- `question.id` 是學習紀錄外鍵，發布後不可重新指派給另一題。
- 刪題使用 deprecated／tombstone；使用者舊紀錄仍可顯示「舊版本題目已下架」。
- 修改題幹但學習意義相同可保留 ID 並遞增 `revision`；正確答案或能力目標實質改變時建立新 ID。

## 權利與公開倉庫

正式題庫每題須有 `rightsStatus`。只可發布 `cleared`、`official-open-data` 或 `public-domain`；`synthetic` 只能用於測試。官方網站可公開閱讀不必然代表可整批重製，仍需保存使用依據。

`accuracyStatus=official-reference-reviewed` 表示已逐題比對主管機關公開參考題文、選項、印刷答案與明顯衝突，但未宣稱每題均完成獨立技術來源驗證。只有在 App 清楚揭露官方參考資料限制、隔離明顯衝突／刪題／法規過渡題並經 Owner 核准的「參考題庫模式」才可使用；不得把此狀態描述為官方認證或正式測試答案。

本專案官方題庫的使用依據、顯名義務與非背書條件見 [[Docs/04_題庫與內容/官方題庫授權評估]]。

## 學習資料

MVP 無帳號、無伺服器、無分析 SDK；收藏、筆記、錯題、作答與考試紀錄只存本機。診斷匯出若後續加入，必須由使用者主動操作、預設去識別且不包含題庫全文。
